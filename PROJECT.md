# Formcatch

Проект на олимпиаду FIRST STEP → цель INFOMATRIX.

## Суть

Одна строка кода на любом сайте — и все уже существующие формы сами собираются в одну таблицу.
Ничего не переделываешь, программист не нужен, подключение < 1 минуты.

**Отличие от конкурентов (для жюри):**
- Google Forms — заставляет заменить форму на свою.
- Формы Tilda и Tilda CRM («Заявки») — работают только на Tilda; у Formcatch одна таблица для любых сайтов и нескольких сайтов сразу.
- CRM (Bitrix24, amoCRM) — нужен программист и настройка.
- Formcatch — перехватывает формы, которые УЖЕ есть, на любой платформе.

## Решения (зафиксированы)

| Вопрос | Решение |
|---|---|
| Как подключается | 1 строка кода (`<script>`), вставляется в Tilda / Wix / WordPress / любой HTML |
| Откуда заявки | Автоперехват существующих форм сайта |
| Нет форм на сайте | Показываем запасную мини-форму «Оставить заявку» (имя + телефон). Только если на всём сайте форм нет |
| Поля | Автоугадывание (имя / телефон / email), без настроек. Пароли и карты не забираем никогда |
| Защита | Привязка к домену (запоминается при первой заявке) + лимит заявок с устройства + ловушка для ботов |
| Кабинет | Сайт Formcatch: вход через Google, несколько сайтов на аккаунт, таблица + статистика + «Скачать Excel» |
| Уведомления | Нет. Владелец сам заходит в кабинет |
| Статусы / Telegram / Instagram | Нет |
| Языки | RU + EN |
| Стек | JavaScript (скрипт + кабинет) + Supabase (база, вход, приём заявок) |
| Деньги | Бесплатно. План роста — только на слайде |
| Пилоты | 3–10 реальных бизнесов С сайтами, замер времени подключения |
| Срок | > 3 месяцев |

## Известные риски

1. Нет уведомлений — заявка может «остыть». Жюри может спросить.
2. Автоперехват — самая сложная часть. Формы внутри iframe (встроенные Google Forms и т.п.) перехватить нельзя — запрет браузера.
3. Главная цифра («подключили за N сек») появится только с пилотами, у которых есть сайт.
4. Вставка своего кода платная на конструкторах: Tilda — платный тариф + подтверждённые email и телефон; Wix — платный тариф + свой домен. Для реальных бизнесов с формами заявок это обычно уже есть.

### Этап 0. Подготовка — готово (2026-10-06)

**Сделано:**
- `git` — история версий, любую ошибку можно откатить.
- Структура папок:
  - `widget/` — скрипт, который владелец вставляет на сайт (`formcatch.js`);
  - `dashboard/` — кабинет владельца;
  - `supabase/` — база и серверные функции;
  - `test-site/` — тестовый стенд.
- Тестовый стенд `test-site/index.html` — 7 видов форм с реальных сайтов, у каждой написано, что должен сделать скрипт:
  1. обычная форма → перехват;
  2. AJAX-форма с полями `field_1/field_2` → перехват, поля по подписям;
  3. форма с паролем и картой → пароль/карта НЕ уходят;
  4. «форма» без тега `<form>` → перехват;
  5. попап, создаётся после загрузки → перехват;
  6. форма в iframe → НЕ перехват (запрет браузера);
  7. поиск по сайту → НЕ перехват.
- Доп. страницы: `thanks.html` (после отправки), `about.html` (страница без форм на сайте с формами → запасной кнопки быть не должно), `no-forms/` (сайт без форм → запасная кнопка должна появиться).
- Все страницы уже подключают `<script src="/widget/formcatch.js" data-site="...">` — ровно так, как это сделает владелец.

**Зачем:** перехват форм — самая рискованная часть. Стенд даёт проверку каждого случая за секунды, без реальных сайтов.

**Как запустить:** из корня проекта `python -m http.server 8080` → http://localhost:8080/test-site/ (или конфигурация `test-site` в `.claude/launch.json`).

**Проверено:** все 4 страницы отвечают 200; во всех 7 случаях «сайт» ведёт себя как настоящий (AJAX-ответ, попап создаётся, кнопка без формы срабатывает, iframe с формой внутри). `formcatch.js` пока 404 — пишется на этапе 1.

**Перенесено:** создание проекта Supabase → этап 2 (там он впервые нужен). Используем **свой** аккаунт Supabase Вани — подключённый в среде Supabase принадлежит другому человеку, его не трогаем.

### Этап 1. Скрипт автоперехвата — готово (2026-10-06)

**Сделано:** `widget/formcatch.js` (~8 КБ, без библиотек).
- **Обычные формы** — один обработчик `submit` на весь документ в фазе захвата: срабатывает раньше кода сайта, ловит формы, появившиеся после загрузки (попапы), и AJAX-формы.
- **Формы без `<form>`** — обработчик `click`: кнопка с текстом вроде «Отправить / Оставить заявку / Записаться» → берём поля из ближайшего блока (до 6 уровней вверх).
- **Подписи полей** — из `<label>`, `aria-label`, `placeholder`, иначе `name`. Поэтому `field_1` превращается в «Ваше имя».
- **Никогда не забираем:** пароли, номера карт / CVC (по типу, `autocomplete`, имени поля), скрытые и файловые поля. Поиск по сайту игнорируется.
- **Отправка** — `navigator.sendBeacon` (доходит даже если страница сразу уходит на «Спасибо»), запасной вариант `fetch keepalive`. Тип `text/plain` — без лишнего CORS-запроса.
- **Защита сайта:** скрипт ничего не отменяет (`preventDefault` не вызывается), все ошибки глушатся, двойное подключение игнорируется, одинаковая заявка дважды за 2 сек не уходит.
- Настройки из тега: `data-site` (ID сайта, обязателен), `data-endpoint` (адрес сервера — появится на этапе 2), `data-debug` (лог в консоль).

**Формат заявки:** `{ site, page, title, kind: form|formless, fields: [{label, name, type, value}], sentAt, v }`.

**Проверено в браузере на стенде (все 7 случаев):**
| Случай | Результат |
|---|---|
| 1. Обычная форма с переходом | ✅ поймана (4 поля), страница «Спасибо» открылась |
| 2. AJAX, поля `field_1/2` | ✅ поймана, поля «Ваше имя», «Телефон» |
| 3. Пароль + карта | ✅ ушли только «Имя» и «Логин» |
| 4. Без `<form>` | ✅ поймана (`kind: formless`) |
| 5. Попап после загрузки | ✅ поймана |
| 6. iframe | ✅ не поймана (как и ожидалось) |
| 7. Поиск | ✅ не поймана |
- Сайт во всех случаях работает как без скрипта (сообщения «Спасибо» появляются).
- Сетевая отправка: с `data-endpoint` ушёл реальный `POST` (сервер пока отвечает 501 — его нет, это этап 2).

**Изменение стенда:** форма случая 1 переведена на `method="get"` — локальный `python http.server` не принимает POST.

**Известные ограничения (проверим на этапе 3):** формы, которые сайт отправляет без события `submit` и без кнопки с понятным текстом (например, кнопка-иконка), не поймаются.

### Этап 2. Приём заявок — готово (2026-10-06)

**Сервер:** свой проект Supabase Вани `formcatch` (регион Frankfurt).
Адрес приёма заявок: `https://gdevndktdjppgmmusalo.supabase.co/functions/v1/collect` — прописан в скрипте по умолчанию, владельцу достаточно `data-site`.

**Сделано (файлы в `supabase/`):**
- `migrations/001_init.sql` — таблицы:
  - `sites` — сайты (id = `data-site`, владелец, домен, «подключён в…»);
  - `leads` — заявки (поля в JSON, домен, хэш IP).
  - Правила доступа (RLS): владелец видит только свои сайты и заявки.
  - Функция `submit_lead` — единственный способ записать заявку, вызывать её может только сервер.
- `functions/collect/index.ts` — серверная функция (Edge Function): принимает заявку от скрипта, чистит её, проверяет и передаёт в `submit_lead`. Проверка JWT выключена: скрипт на чужих сайтах ключей не знает.
- `seed_test.sql` — тестовые сайты `test-site` и `test-no-forms`.
- Скрипт `formcatch.js`: добавлены признак живого человека (`human` — были ли настоящие нажатия/ввод, браузер помечает их `isTrusted`) и время на странице (`tp`).

**Защита (как отвечать жюри):**
| Угроза | Защита |
|---|---|
| Бот шлёт заявки напрямую | Нет реальных действий человека или < 1,5 сек на странице → заявка игнорируется |
| Кто-то скопировал код вставки себе на сайт | Домен привязывается по первой заявке; заявки с чужого домена сохраняются скрытыми (`blocked`) — владелец их не видит |
| Заваливание заявками | ≤ 5 заявок за 10 мин с одного устройства, ≤ 300 в час на сайт |
| Подделка IP, чтобы обойти лимит | Не работает — проверено: IP подставляет Supabase |
| Огромные заявки | ≤ 20 КБ, ≤ 50 полей, ≤ 1000 символов в поле |
| Утечка личных данных | IP не храним, только хэш; пароли и карты скрипт не собирает (этап 1) |

Честно: 100% защиты от спама у кода, который виден всем, не бывает — защита отсекает массовый и автоматический спам.

**Проверено:**
- Стенд в браузере, настоящий ввод с клавиатуры и клик мышью → заявка ушла (`sendBeacon` вернул `true`) и дошла: из 5 мест лимита 2 уже были заняты заявками браузера.
- Прямые запросы к серверу:
  - неизвестный сайт → `404 unknown_site`;
  - бот (`human: false`) → `202 ignored`;
  - < 1,5 сек на странице → `202 ignored`;
  - без Origin → `403 no_origin`;
  - свой домен → `201 ok`;
  - чужой домен → `202 blocked`;
  - 4-я заявка за 10 мин → `429 rate_limited`;
  - подделка `X-Forwarded-For` → всё равно `429`.

**В базе остались тестовые заявки** (стенд + проверки) — это нормально, на этапе 7 они покажутся в таблице.

**Найдено и исправлено на Tilda (скрипт v0.2.0):**
1. **Tilda отправляет форму в обход события `submit`** (перехватывает клик и шлёт данные в фоне) → скрипт заявку не видел.
   *Исправление:* клик по кнопке отправки → если `submit` не случился, скрипт сам собирает поля сразу после обработчика сайта.
   Если сайт показал видимую ошибку (неверный email) или браузер не пустил форму — заявку не шлём.
2. **Ложная «ошибка»:** у Tilda в форме всегда есть блок ошибок нулевой высоты с текстом.
   *Исправление:* ошибкой считаем только реально видимый элемент (ненулевой размер, видимый текст).
3. **Телефон Tilda:** видимое поле без кода страны + скрытое `Phone` с полным номером.
   *Исправление:* берём скрытые поля с именами `phone/tel/email/name`, а части номера `tildaspec-*` и ловушку ботов Tilda `form-spec-*` пропускаем.
   Итог: `Phone = +373 7011-1122`.

  - пустая форма → заявки нет;
  - неверный email → заявки нет, Tilda показала ошибку;
  - правильная форма → заявка со всеми полями и полным телефоном.
- База: строки `test-tilda` с доменом `record-linked-bream.tilda.ws`, `blocked = FALSE` (скриншот Table Editor).

- Время «клиент заполнил форму → заявка в базе» на Tilda: ~30–40 сек (почти всё — заполнение формы; доставка — доли секунды). Время установки владельцем замерим на пилотах (секундомер — этап 6).
- Стенд после правок: 7/7 случаев, дублей нет.

**Наблюдения для проекта:**
- **Tilda:** блок T123 только на платном тарифе и только после подтверждения email и телефона (защита Tilda от фишинга). В инструкцию владельцу: «если Tilda просит подтвердить телефон — это один раз».

- **У Tilda есть своя CRM** («Заявки») — ответ жюри в разделе «Отличие от конкурентов».

### Этап 4. Автоугадывание полей — готово (2026-10-07)

**Зачем:** раньше заявка приходила списком «подпись → значение», а на каждом сайте подписи свои (`field_1`, `Your name`, «Как к вам обращаться?»). Теперь у каждой заявки три одинаковые колонки — **Имя / Телефон / Email**, с какого бы сайта она ни пришла. Это основа таблицы, статистики и Excel (этап 7).

**Сделано:**
- **Скрипт `formcatch.js` v0.3.0** — каждому полю ставит роль `name` / `phone` / `email` и прикладывает к заявке сводку `contact: {name, phone, email}`.
  - Подсказки: тип поля (`email`, `tel`), `autocomplete`, подпись, `name`/`id`, `placeholder`. Русский и английский.
  - Роль ставится, только если **значение подходит по формату**: «позвоните вечером» — не телефон, «нет» — не email, имя без цифр и `@`.
  - Ловушки: «Название компании», «Логин», «Город», «Номер заказа», «Промокод» — не имя и не телефон. Комментарии (`textarea`), списки и галочки не угадываются.
  - Подписей нет совсем (`field_1`) — угадываем по значению: email по `@`, телефон по `+` или 10–12 цифрам с 7/8, имя — единственное «словесное» поле.
  - Имя и фамилия в разных полях склеиваются: «Иван Петров».
  - `data-endpoint="none"` — для тестов: скрипт ничего не отправляет.
- **База — `supabase/migrations/002_contact_columns.sql`:** колонки `name`, `phone`, `email` в `leads`; `submit_lead` принимает `p_contact`. Старые заявки заполнены по подписям и формату.
- **Сервер `collect`:** пропускает только роли `name/phone/email` и **перепроверяет формат** сводки (скрипт на чужом сайте можно подделать — сервер не верит на слово).
- **Стенд `test-site/fields.html`:** 11 случаев с ожиданиями, страница сама прогоняет все формы и пишет «Пройдено N из 11».

**Выкладка:** SQL и деплой функции подтверждал Ваня (изменения в рабочем проекте — только руками владельца). Скрипт в Storage заменён.
*Урок:* загрузка файла с тем же именем в Supabase Storage не заменяет его, а создаёт `formcatch (1).js` — старый файл надо удалить, новый переименовать.

**Проверено:**
- `fields.html` — **11 из 11**; старый стенд — пароль и карта по-прежнему не уходят, «Логин» не принят за имя.
- Живые заявки (настоящий ввод и клики) → строки в базе:
  | Откуда | name | phone | email |
  |---|---|---|---|
  | Стенд, AJAX-форма `field_1/field_2` | Валерия | 8 (912) 777-88-99 | — |
  | Стенд, обычная форма | — (вписано «Проверка Этап4» — цифра, не имя) | +7 900 444-55-66 | stage4@example.com |

### Этап 5. Запасная мини-форма — готово (2026-10-07)

**Зачем:** у сайта без единой формы клиенту некуда оставить заявку — Formcatch сам добавляет кнопку «Оставить заявку» (имя + телефон). На сайтах с формами кнопки быть не должно — даже на страницах вроде «О нас», где форм нет.

**Главная сложность:** страница не видит другие страницы сайта. Решение — сервер помнит, есть ли у сайта формы (`sites.form_found`):
1. Страница **с формой** один раз сообщает серверу «форма есть» (`GET collect?site=ID&form=1`).
2. Страница **без форм** спрашивает сервер (`GET collect?site=ID`) → `none` — показываем кнопку, `found` — нет.
3. Ответ «форма есть» запоминается в браузере посетителя (`localStorage`) — повторно сервер не спрашиваем.

**Сделано:**
- **Скрипт `formcatch.js` v0.4.0:**
  - «Форма на странице» — `<form>` с полем ввода (не поиск), поле ввода вне форм или встроенная форма сервиса (Google Forms, Typeform, Битрикс, amoCRM…) в iframe;
  - проверка через 1,5 сек после загрузки страницы (конструкторы дорисовывают формы не сразу);
  - форма появилась позже (попап, ленивая загрузка) → кнопка сама исчезает, сервер узнаёт «форма есть»;
  - мини-форма в Shadow DOM — стили сайта её не ломают, её стили не трогают сайт;
  - проверка ввода: без имени и с неправильным телефоном не отправляется, показывает ошибку;
  - заявка уходит с `kind: fallback`, имя и телефон сразу с ролями (этап 4);
  - RU / EN по языку сайта; работает с клавиатуры (Tab, Enter, Esc), на телефоне не вылезает за экран;
  - владелец может выключить кнопку: `data-fallback="off"`.
- **База — `supabase/migrations/003_form_found.sql`:** функция `site_ping` (ответ `found | none | unknown_site`). «Форма есть» принимается только с домена сайта.
- **Сервер `collect`:** отвечает на `GET` — вопрос «есть ли форма».

**Защита:** подделать «форма есть» можно только с домена сайта — и максимум это спрячет запасную кнопку. Заявки с мини-формы проходят все проверки этапа 2 (человек, лимиты, домен).

**Проверено:**
- До выкладки — на стенде с локальным заменителем сервера: все сценарии ниже + телефон 375 px + английский сайт.
- После выкладки — на настоящем сервере, настоящим вводом и кликами:
  | Сценарий | Результат |
  |---|---|
  | «Лаванда» (`no-forms/`, форм нет) | ✅ кнопка есть |
  | Пустая форма / телефон «123» | ✅ не отправлено, ошибка |
  | Имя + телефон | ✅ «Спасибо!»; в базе заявка №15: `test-no-forms`, `fallback`, «Марина Лаванда», «+7 777 123 45 67» |
  | «О нас» до захода на главную | кнопка есть (сервер ещё не видел форм сайта) — ожидаемо |
  | Главная стенда | ✅ кнопки нет, `form_found = true` |
  | «О нас» после главной, и в «новом браузере» | ✅ кнопки нет |
  | Tilda | ✅ кнопки нет, `form_found = true` |

- Сервер: сайт без форм → `none`, несуществующий сайт → `unknown_site`, запрос без домена → `no_origin`.

**Найдено при проверке:** файл, загруженный через панель Supabase, отдаётся с `Cache-Control: public, max-age=3600` — браузер посетителя хранит скрипт до **1 часа**. На этапе 4 заголовок проверяли запросом HEAD, а он отвечает иначе, чем обычная загрузка. Итог: обновление скрипта доходит до всех посетителей в течение часа (так же работают Google Analytics, Яндекс Метрика). Для олимпиады это нормально; проверять заголовки — только обычным GET.

**Ограничения (честно):**
- Пока у сайта не было ни одного посетителя на странице с формой, кнопка может появиться на страницах без форм. Обычно первым главную открывает сам владелец при подключении.
- Если владелец убрал все формы с сайта, отметка «форма есть» остаётся — сброс сделаем в кабинете (этап 6).
- **Этап 9:** под мини-формой нужна строка согласия на обработку персональных данных со ссылкой на политику конфиденциальности.
